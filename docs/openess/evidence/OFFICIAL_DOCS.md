## Verified findings

### Installation and identity

- Openness is installed as a TIA Portal setup option, and its version must match the installed STEP 7/WinCC version. Side-by-side older Openness versions can remain installed. [O02]
- Installation creates the local `Siemens TIA Openness` group, but installation alone does not grant access. The user must be a direct or indirect member, and must log on again after membership changes. TIA Portal does not manage this Windows group. [O02, O03]
- Siemens lists 64-bit Windows/TIA Portal with 32-bit, 64-bit, or AnyCPU user applications, and Visual Studio 2017 or later with .NET Framework SDK 4.8 for development. [O01]
- Siemens documents Openness remoting as an `IpcChannel` with `ensureSecurity=false`, priority 1, full type-filter level, and an `authorizedGroup` corresponding to the built-in everyone account. This is a transport implementation fact, not an application authorization model; Simon must provide its own strict worker boundary and operation policy. [O01]

### Loading and connecting

- A client can start TIA Portal with or without the UI, or attach to a running instance. Siemens recommends an application configuration file for assembly loading in most cases. It says this route honors strong names, while its shown `AssemblyResolve` approach does not detect malicious modification in the same way. [O05]
- `TiaPortal.GetProcesses()` enumerates running instances without needing an existing `TiaPortal` instance. A process may need startup time before it responds to Openness requests. [O05]
- Attaching shows the Openness firewall prompt: allow once, reject, or always allow. Three rejected registry prompts produce `EngineeringSecurityException`. Whitelisting records the application path, last-write timestamp, and SHA-256-derived file hash in the registry. [O05, O06]
- Openness has no compatibility mode: required TIA option packages and HSPs used by a project must be installed. [O05]

### Exclusive access and transactions

- Siemens highly recommends exclusive access even though it is not mandatory. It should be disposed with `using`; a second exclusive-access attempt within an existing one produces a recoverable exception. The user can request cancellation, exposed through `IsCancellationRequested`. [O07]
- A transaction groups operations into one undo unit and can improve performance. Its description cannot be null or empty. [O08]
- Disposal rolls back unless `CommitOnDispose()` has been requested. An exception after that request still causes rollback on disposal. `CanCommit` and `CommitRequested` expose transaction state. [O08]
- Siemens explicitly disallows these inside a transaction: compile, go online/offline, project-text import/export, global-library open/close, project create/open/open-with-upgrade/save/save-as/close. [O08]

### Projects

- `Projects.Open` is for current-version projects. `OpenWithUpgrade` opens a project from the previous version by creating an upgraded project; older-than-previous versions produce an exception. [O10]
- Protected projects support UMAC credential callbacks and, since V17, desktop SSO, anonymous, interactive, and credential authentication modes. [O10]
- One primary and multiple secondary projects can be open. Secondary projects are always read-only and are not shown in project navigation when attached to a UI instance. Composition indices can change when projects close. [O10]
- Read-only projects support getters, compositions, services, find/navigation, object existence checks, and selected non-modifying actions. They do not imply the full read-write feature set. [O11]
- `Save()` and `SaveAs(...)` are explicit project operations and must be outside a transaction. [O08, O12]

### Compilation

- Compilation requires connection, an open project, and all devices offline. Supported targets include devices, device items, code/data blocks, HMI targets, PLC software/types, and block/type groups. [O13]
- Compilation is service-based through `ICompilable`. Consumers must inspect result state, warning/error counts, and recursively nested messages. Compiler timestamps are UTC. [O13]
- A password-protected safety program requires the necessary safety login or the compile is cancelled with an exception. [O13]

### Exchange formats

- XML block export requires the PLC not to be online and exports consistent FB, FC, OB, global DB, and user-data-type content for supported STL, FBD, LAD, GRAPH, and SCL representations. [O14]
- V20 adds `LibraryTypeGuid` as a read-only SIMATIC ML attribute for applicable PLC blocks/types. Library identity attributes can be ignored on import, producing a non-type-connected block/type. [O14]
- Program-block document export/import is the SIMATIC SD document route. Results expose operation state, messages, and exported/imported file or block collections. Import options include `None`, `Override`, `Skipinactiveculture`, and `ActiveInactiveculture`. [O15, O16]
- Source generation requires the PLC not online. It produces UTF-8 source; Siemens requires UTF-8 with BOM for writing special characters. `None` exports selected objects, while `WithDependencies` includes dependencies. Block source supports STL/SCL only and enforces `.awl`, `.scl`, `.db`, or `.udt` extensions by object kind. [O17]
- External-source creation supports STL, SCL, DB, and UDT files; external-source subgroups are not supported. [O18]

### Cross references

- The service returns textual cross-reference data plus an underlying engineering object where available. [O19]
- STEP 7 member objects such as DB/FB/FC/tag/UDT members do not implement `IEngineeringObject`; their `UnderlyingObject` is null, but textual fields remain available and must be preserved. [O19]
- Results are structured as source objects, references, and locations, with names, addresses, type names, devices, paths, reference/access types, and related textual fields. [O19]

## Extraction limitations

- This was static documentation reading, not execution of Openness operations.
- Rendered text occasionally contains character-decoding artifacts from the Siemens viewer; claims were recorded only when the meaning was clear and corroborated by context or the installed API.
- The page ledger covers Simon's likely initial integration seams, not all 188,106 words or every subsystem in the V20 manual.
